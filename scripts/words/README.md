# Word list pipeline

Builds open-license Turkish word lists for the word game from the Hunspell `hunspell-tr`
dictionary. See `../../data/words/README.md` for the output format and counts.

## Usage

```sh
pip install -r scripts/words/requirements.txt
python3 scripts/words/build_word_lists.py
```

Deterministic: the dictionary is fetched from a pinned commit, and the same input always
produces the same output files under `data/words/`.

## Modules

- `hunspell_source.py`: pinned-commit download/cache and `.dic` parsing.
- `turkish.py`: Turkish-aware case conversion and alphabet validation (no `Q`/`W`/`X`).
- `inflection.py`: heuristic to drop nominal inflected forms (possessive/case/plural) from
  the valid-word list when their root is itself an independent, reasonably frequent word.
  Verb-conjugation stripping and consonant softening (p/ç/t/k -> b/c/d/ğ) were both tried
  and removed — see "Quality notes" below for why.
- `candidates.py`: zipf-frequency filter, mastar (`-mak`/`-mek`) exclusion, family-safety
  blocklist, the `needs_review` heuristic, and `is_likely_english` (an English loanword
  filter: `ENGLISH_ZIPF_MARGIN = 1.5`, flagging a word whose English `wordfreq` zipf
  score is at least that much higher than its Turkish one). The margin alone misflags a
  handful of real Turkish words as English; `turkish_allowlist.txt` (exact match, checked
  before the margin) is the escape hatch for those — see "Quality notes" below.
- `build_word_lists.py`: orchestrates the above and writes `data/words/`.
- `blocklist.txt`: short, hand-curated list of explicit/vulgar roots, prefix-matched
  against candidates unless the line is prefixed with `=`, which blocks only that exact
  word (for an entry whose plain spelling also has an unrelated, legitimate meaning as a
  longer word's prefix — e.g. `=kaşar` blocks the slang word "kaşar" but not "kaşarlı",
  a type of cheese). Do not quote its contents in reports, PRs or commit messages.
- `turkish_allowlist.txt`: short, hand-curated, exact-match list of real Turkish words
  that `is_likely_english` would otherwise drop (e.g. "fire", "step", "sure", "moment" —
  all far more common in English in absolute `wordfreq` terms, but genuine Turkish words).
  Checked before the English/Turkish margin, so these always survive regardless of the
  margin value. Add to it only when a specific false positive is confirmed, not
  speculatively.
- `test_build_word_lists.py`: unittest suite (run with `python3 -m unittest` from this
  directory).

## Answer review

- `answer_pool.py --length N`: ranks `data/words/candidates-N.csv` by frequency and writes the
  top 600 to `data/words/review/pool-N.txt`.
- `validate_labels.py --length N [--pool daily|unlimited]`: checks the model-written labels
  against the pool for that mode and prints accepted/rejected counts and errors as JSON. A
  label needs only `word` + `decision` (`accept`/`reject`/`unsure`), plus a `reason` for
  `reject`/`unsure`; any other field (legacy `meaning`/`category`/`context`) is ignored. Words
  carry no meaning or context in either pool.
  - `--pool daily` (default): pool `data/words/review/pool-N.txt`, labels
    `data/words/review/labels-N.jsonl`, accepted words go to `review-N.csv` (`word` column
    only) for import.
  - `--pool unlimited`: pool `data/words/review/unlimited-pool-N.txt` (from
    `unlimited_pool.py`), labels `data/words/review/labels-unlimited-N.jsonl`, accepted words
    go to `unlimited-N.csv` (`word` column only).
  - Exits 1 without writing the CSV when there are any errors.
- `test_validate_labels.py`: unittest suite for the validator.

## Unlimited pool

- `unlimited_pool.py`: builds the unlimited-mode candidate pool per length (4, 5, 6) from the
  same Hunspell + wordfreq pipeline as `build_word_lists.py`, with a lower frequency floor
  (`UNLIMITED_ZIPF_FLOOR = 2.5`, vs. the daily pipeline's `ZIPF_THRESHOLD = 3.0` in
  `candidates.py`) so unlimited mode has a larger pool than the daily one. Reuses
  `candidates.py` (mastar exclusion, blocklist), `inflection.py` (inflected-form heuristic) and
  `turkish.py` (alphabet/case). Excludes any word already in that length's daily pool
  (`pool-N.txt`) or accepted daily review file (`review-N.csv`), so no word can answer both
  modes. Deterministic (same pinned dictionary commit, same filters) and writes one word per
  line to `data/words/review/unlimited-pool-N.txt`. No model labels are generated by this
  script; labelling (decision + reason only) goes through `validate_labels.py --pool unlimited`.
- `test_unlimited_pool.py`: unittest suite for the pool builder (filters, exclusion, and the
  frequency floor — inclusive at exactly `UNLIMITED_ZIPF_FLOOR`, same as the daily pipeline's
  `ZIPF_THRESHOLD` — with `zipf_frequency` mocked so the floor itself is tested
  deterministically; the inflection heuristic's own root-frequency check runs unmocked, same
  as `test_build_word_lists.py`).

## Quality notes (manual sampling)

A manual sample of the unlimited pool found a meaningful share of unsuitable entries: English
words, proper nouns, verb conjugations, possessive/case forms missed because of consonant
softening, and a handful of vulgar/sexual/slur words that slipped past `blocklist.txt`.

A first pass tried to fix verb conjugations and consonant softening inside `inflection.py`
itself. Both were reverted (main-loop decision) after testing showed they dropped real,
independent words — not just inflected junk:

- Verb-conjugation suffixes (`-dık`/`-tık`/`-miş`/`-acak`, even restricted to "safer"-looking
  ones) wrongly flagged lexicalized nouns that happen to share a verb's surface form: "antik"
  (antique), "sadık" (loyal), "gümüş" (silver), "koltuk" (armchair), "mantık" (logic),
  "geçmiş" (the past), "altmış" (sixty), "içecek" (a drink), "gelecek" (the future) are all
  independent dictionary words, not conjugated verbs, but each one also parses as some root +
  a verb suffix.
- Consonant softening wrongly flagged independent words whose "hardened" root happened to
  collide with an unrelated real word: "düğünü"/"tribünü" (wedding/stand, accusative) ->
  hardened root collided with other real short words; "yığına" (to the pile) and "kendini"
  (yourself) similarly collided.

Heuristics like these cannot make the unlimited pool family-safe or lexically clean on their
own — the real gate for unlimited-pool quality is **model labels + the eval gate (Plan 010
U5/U6) + the blocklist**, not a bigger suffix list. So this pipeline is kept deliberately
conservative: a filter change must not remove a good word without an explicit, tested
exception for it, even if that means some verb forms, proper nouns and non-English loanwords
still get through to be caught by labelling/review instead. `valid-N.txt` (the player-facing
guess dictionary, every length), `pool-5.txt`, `pool-6.txt` and the label/review files are
unchanged; `pool-4.txt` was regenerated on the owner's decision of 2026-10-06 (Plan 008).

The English-loanword filter (`is_likely_english`) is not clean on its own: a later review
found it wrongly dropping real Turkish words (FİRE, STEP, SURE, MOMENT — all words that score
higher in absolute English `wordfreq` terms than Turkish, but are genuine Turkish vocabulary).
Rather than loosen `ENGLISH_ZIPF_MARGIN` (which would let more real English loanwords back
in), these four were added to `turkish_allowlist.txt`, an exact-match list checked before the
margin runs; each is covered by a test asserting it survives. The same review found two
English words slipping *past* the filter the other way — BİRD and LAMB — added to
`blocklist.txt` as exact (`=`) entries rather than by lowering the margin, which would have
reopened the false-positive problem above.

What this pass also keeps: the `blocklist.txt` additions found by manually scanning the
generated pool files (not reproduced here — see the file's own note), covering explicit
sexual/anatomical terms, a racial slur, prostitution/adultery terms, a crude imperative, two
"pervert" words and several drug names. The anti-gay slur category was only partly covered by
the pre-existing `ibne`/`puşt` entries: a later review found HOMO had slipped into the
unlimited pool and added it as an exact (`=homo`) entry, along with two sexual terms (SEKSE,
SEVİŞ, as `=sekse`/`=seviş`) that had also slipped through — all three as exact matches so
that unrelated longer words sharing the same prefix (SEKSEN, HOMOJEN) are not blocked. Two
ambiguous drug-adjacent words ("afyon"/"haşhaş") were deliberately left unblocked: both are
far more commonly used for their legitimate meanings in Turkish (a province name; poppy seed
as a food topping) than for the drug, so blocking them would remove a good word for most of
its uses.

**The unlimited pool must not be imported into the game until Plan 010 U5/U6 (the label eval
gate) has passed.** Heuristic filtering alone is not a family-safety gate.
