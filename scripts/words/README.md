# Word list pipeline

Builds open-license Turkish word lists for the word game from the Hunspell `hunspell-tr`
dictionary. See `../../data/words/README.md` for the output format and counts.

## Usage

```sh
pip install -r scripts/words/requirements.txt
python3 scripts/words/build_word_lists.py
```

Deterministic: the dictionary is fetched from a pinned commit, and the same input always
produces the same output files under `data/words/`.

## Modules

- `hunspell_source.py`: pinned-commit download/cache and `.dic` parsing.
- `turkish.py`: Turkish-aware case conversion and alphabet validation (no `Q`/`W`/`X`).
- `inflection.py`: heuristic to drop inflected forms when their root is itself an
  independent, reasonably frequent word, including consonant softening (p/ç/t/k ->
  b/c/d/ğ, e.g. "kitabına" -> "kitap"). Two scopes: `include_verbs=False` (the
  default for `build_valid_set`, i.e. `valid-N.txt`, the player-facing guess
  dictionary) only strips nominal forms (possessive/case/plural); `include_verbs=True`
  (the default otherwise — candidate/unlimited-pool selection) also strips common verb
  conjugations (narrative past "-miş", future "-ecek"/"-acak", the "-dık" participle).
  Several short suffixes were tried and deliberately dropped because they collided
  with unrelated, often very common, standalone words even with the known-word +
  frequency guard — see the comments above `NOMINAL_SUFFIXES`/`VERB_SUFFIXES` for
  concrete examples ("kalem" is not "kale" + possessive, "zaman"/"insan"/"kazan" are
  not a verb + "-an" participle).
- `candidates.py`: zipf-frequency filter, mastar (`-mak`/`-mek`) exclusion, family-safety
  blocklist, the `needs_review` heuristic, and `is_likely_english` (an English loanword
  filter: `ENGLISH_ZIPF_MARGIN = 1.5`, flagging a word whose English `wordfreq` zipf
  score is at least that much higher than its Turkish one).
- `build_word_lists.py`: orchestrates the above and writes `data/words/`.
- `blocklist.txt`: short, hand-curated list of explicit/vulgar roots. Prefix-matched against
  candidates. Do not quote its contents in reports, PRs or commit messages.
- `test_build_word_lists.py`: unittest suite (run with `python3 -m unittest` from this
  directory).

## Answer review

- `answer_pool.py --length N`: ranks `data/words/candidates-N.csv` by frequency and writes the
  top 600 to `data/words/review/pool-N.txt`.
- `validate_labels.py --length N [--pool daily|unlimited]`: checks the model-written labels
  against the pool for that mode and prints accepted/rejected counts and errors as JSON. A
  label needs only `word` + `decision` (`accept`/`reject`/`unsure`), plus a `reason` for
  `reject`/`unsure`; any other field (legacy `meaning`/`category`/`context`) is ignored. Words
  carry no meaning or context in either pool.
  - `--pool daily` (default): pool `data/words/review/pool-N.txt`, labels
    `data/words/review/labels-N.jsonl`, accepted words go to `review-N.csv` (`word` column
    only) for import.
  - `--pool unlimited`: pool `data/words/review/unlimited-pool-N.txt` (from
    `unlimited_pool.py`), labels `data/words/review/labels-unlimited-N.jsonl`, accepted words
    go to `unlimited-N.csv` (`word` column only).
  - Exits 1 without writing the CSV when there are any errors.
- `test_validate_labels.py`: unittest suite for the validator.

## Unlimited pool

- `unlimited_pool.py`: builds the unlimited-mode candidate pool per length (4, 5, 6) from the
  same Hunspell + wordfreq pipeline as `build_word_lists.py`, with a lower frequency floor
  (`UNLIMITED_ZIPF_FLOOR = 2.5`, vs. the daily pipeline's `ZIPF_THRESHOLD = 3.0` in
  `candidates.py`) so unlimited mode has a larger pool than the daily one. Reuses
  `candidates.py` (mastar exclusion, blocklist), `inflection.py` (inflected-form heuristic) and
  `turkish.py` (alphabet/case). Excludes any word already in that length's daily pool
  (`pool-N.txt`) or accepted daily review file (`review-N.csv`), so no word can answer both
  modes. Deterministic (same pinned dictionary commit, same filters) and writes one word per
  line to `data/words/review/unlimited-pool-N.txt`. No model labels are generated by this
  script; labelling (decision + reason only) goes through `validate_labels.py --pool unlimited`.
- `test_unlimited_pool.py`: unittest suite for the pool builder (filters, exclusion, and the
  frequency floor — inclusive at exactly `UNLIMITED_ZIPF_FLOOR`, same as the daily pipeline's
  `ZIPF_THRESHOLD` — with `zipf_frequency` mocked so the floor itself is tested
  deterministically; the inflection heuristic's own root-frequency check runs unmocked, same
  as `test_build_word_lists.py`).

## Quality notes (manual sampling)

A manual sample of the unlimited pool found a meaningful share of unsuitable entries: English
words, proper nouns, verb conjugations (missed because `is_inflected_form` only covered nominal
forms), and a handful of vulgar/sexual/slur words that slipped past `blocklist.txt`. This pass:
adds the missed offensive roots to `blocklist.txt` (not reproduced here — see its own note),
extends `inflection.py` with consonant softening and a bounded set of verb-conjugation suffixes
(see above), and adds the English-loanword filter. It does **not** fully eliminate unsuitable
entries — bare past tense (`-dı`/`-di`/...), `-sa`/`-se`, and `-an`/`-en` conjugations are
deliberately left unfiltered (too many false positives on common nouns), so some verb forms
and a few proper nouns/loanwords from other languages remain. A follow-up would need a real
verb-root dictionary or a proper-noun list rather than this prefix/suffix heuristic.
